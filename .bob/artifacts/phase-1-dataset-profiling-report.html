7. Target Variable Analysis

Primary ML Target — "Was the order delayed?"

Delivery_Duration_Minutes (15–60 min, mean ≈ 37.5 min) is the direct numeric target for regression. A binary "delayed / on-time" label can be derived by thresholding (e.g., > 45 min = delayed — to be decided in Phase 3).
Order_Status is a secondary classification target (Delivered / Cancelled / In Transit) but has strong class imbalance (85 / 10 / 5 split).
Candidate TargetTypeNotes
Delivery_Duration_MinutesContinuous regressionClean, bounded 15–60 min, no nulls. Primary target.

9. Phase 1 Preprocessing Roadmap

  • Parse datetimes: Convert Order_Time and Delivery_Time from string to datetime64 using format %d-%m-%Y %H:%M.
  • Engineer time features: Extract OrderHour, OrderDayOfWeek, IsWeekend, IsRushHour from Order_Time.
  • Strip whitespace: Already clean — no action needed.
  • Encode categoricals: Ordinal-encode Traffic_Level (Low=0, Medium=1, High=2); label/one-hot encode City, Driver_Vehicle, Payment_Method, Item_Name.
  • Retain all 23 columns — no premature dropping; feature selection deferred to Phase 2.
  • Do not reduce rows yet — dataset reduction deferred to Phase 2.
  • Flag Cancelled / In Transit rows with a boolean column for easy downstream filtering.
  • Compute derived target: After Phase 3 defines the delay threshold, derive a binary IsDelayed column.
  • No imputation needed — zero missing values.
  • Geo columns: Keep raw lat/lon; derived features (haversine distance between driver and restaurant at order-time) can be added in Phase 2.
